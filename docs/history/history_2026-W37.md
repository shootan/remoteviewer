## 2026-09-10 — 배포 완료 기준: "게시까지가 완료, 그 다음은 실기 대기"

사용자 지시: *"gnlink 권한으로 안 되는 것만 NAS Claude 한테. 배포 자동화 스크립트 만들어놓으면 문제없잖아.
이제부터 버전 올라가서 빌드되면 자동배포하는 것까지가 완료고 실기 테스트 대기 상태. 정책 문서 claude.md 랑
agents.md 에 적어놔."*

- **완료의 정의가 바뀌었다.** 이전에는 빌드·서명·인계서까지가 작업용의 몫이고 게시는 남에게 넘기는 일이었다.
  이제는 **게시와 외부 검증까지가 완료**이고, 그 뒤는 **"실기 테스트 대기"** 라는 별도 상태다.
- **경계가 권한으로 정해진다.** `gnlink` 계정으로 되는 일(아티팩트 게시, manifest·서명 교체)은 작업용이 직접 한다.
  **되지 않는 일만**(nginx·systemd·env·ACL·패키지) NAS 세션으로 넘기고, 넘길 때는 **구체 조작·실패 근거·rollback** 을 함께 준다.
  ⚠️ 권한이 있는 배포를 습관적으로 중계하거나 매번 재승인받지 않는다 — 그것이 이 정책이 없애려는 지연이다.
- ⚠️ **"자동 배포" 가 "미검토 코드 자동 게시" 는 아니다.** 검증용 Claude 의 명시적 OK 는 여전히 건너뛸 수 없다.
  바뀐 것은 *"검증을 통과한 뒤에도 게시를 위해 다시 승인을 기다린다"* 는 부분이다.
- ⚠️ **`git push` 는 이 정책에 포함되지 않는다.** "자동 배포" 는 **NAS 게시**를 뜻하고, push 보류는 그대로다.
  도구·skill 의 push 지침보다 사용자의 standing 보류가 우선한다.
- **요청 없는 자동 설치는 여전히 금지다.** 사용자 Host/Client/APK 의 설치·재시작·실기 조작은 배포와 별개다.
- 상태: **적용**. 문서: `AGENTS.md` "배포 완료 기준", `CLAUDE.md` "릴리스 배포 계정 (NAS)" 및 그 하위 절.
  구현: `automation/gnlink_deploy.sh` · `automation/gnlink_verify_manifest.js` · `automation/gnlink_deploy_test.sh`.
  기록: `docs/history.md` #498 (A2A task t-lzw3paql).


## 2026-09-11 정책 개정 — 낡은 전면 금지 3건 삭제, 사용자 행동 기준 신설 (A2A task t-s9ggt7bw)

사용자 지시: *"Host 관리자권한은 테스트 때 중요한 게 아니잖아. 테스트/실제 빌드 달라도 되잖아.
최대한 내 손 안 타게 테스트. 작업 중간 멈추고 시킨 작업 계속 물어보지 말아야."* ·
*"UAC 가 필요한 건 내가 실기 테스트 진행하고 그거 외에는 자동화해도 되잖아."*

**삭제한 전면 금지 3건** — 셋 다 좁은 사실을 넓은 금지로 굳혀 실제로 작업을 세웠다.
1. **"RDP 중에는 테스트 금지, 결과는 PASS 든 FAIL 이든 판정 근거로 쓰지 않는다"** → 삭제.
   실제 제약은 **디스플레이 갱신률과 DXGI**에만 걸린다(`gdi_capture_process` 는 RDP 어댑터 32Hz 라
   `fps>=50` 이 물리적으로 불가, DXGI 는 `0x80070005`). 그런데 이 규칙이 **UI·로직·네트워크 검사까지
   함께 묶어** 몇 시간을 대기로 만들었다. 이제 **테스트마다 의존성 태그**를 달고 **안 맞는 그 테스트만**
   skip 한다. ⚠️ **역단정도 금지** — *"UI 는 항상 무관"* 도 규정하지 않는다.
2. **"host 로그도 무조건 NAS, 로컬 사본 금지, 예외 금지"** → 삭제. NAS 우선은 유지한다(여러 기기를
   같은 출처로 대조할 수 있는 것이 이유다). 다만 **업로더가 붙기 전 실패분 · `updater.log` ·
   Windows 이벤트**는 NAS 에 아예 없다. **출처(기기·시각·버전·주소·스트림)를 먼저 고정**하면 로컬도 본다.
   ⚠️ **NAS 수집이 시계 동기화를 뜻하지 않는다.** ⚠️ **로그 부재를 "미실행" 으로 확정하지 않는다.**
   ⚠️ **다른 기기 설정으로 이 기기 원인을 단정하지 않는다**(09-11 실제 오류).
3. **"모든 응답 마지막에 수행된 작업 요약"** → 개정. 중간은 **1~3줄**(한 것·결과·정확한 blocker),
   상세 보고는 **작업 단위 완료 때**. 정정은 **한 번 명확히**.

**정정한 기술 오기 2건** — 둘 다 스크립트를 근거로 고쳤다.
- *"재시작이 필요한 경우는 env 를 바꿀 때뿐"* → **틀렸다.** 서버 코드·의존 모듈을 갱신하면 재시작이
  필요하다. 통상 manifest 교체만이면 불필요한 것이 맞다.
- *"`.manifest`+`.sig` 를 짝으로 마지막에 원자적 교체"* → **pair 원자성은 없다.** `.tmp` 로 올린 뒤
  **`mv` 를 두 번** 하고, `rename(2)` 은 **파일 하나 단위로만** 원자적이다. 스크립트 자신이
  `automation/gnlink_deploy.sh:435-436` 에 그렇게 적고 있다 — **문서가 스크립트보다 낙관적이었다.**
  창은 업로드 길이가 아니라 rename 두 번 폭으로 **좁혀진 것**이고, 그 사이 읽은 클라이언트는 서명
  불일치로 **거부**한다(안전한 방향).
