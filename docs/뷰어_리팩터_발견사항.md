**코덱스 교차검증**: 원인 확정. 추가로 **두 번째 고착 경로**를 지적받았다 — UI 스냅샷이 새 프레임까지 포함하면 `latest == painted`라 말미 재확인 조건 자체가 성립하지 않아 그 회복 경로마저 안 돈다(이쪽이 더 조용하다). 또 `d3dPresentSuccess=0 ∧ d3dPresentFail=0`만으로는 "WM_PAINT 0회"를 수학적으로 증명하지 못한다는 지적에 따라 `paintEnter` 계측을 넣었다.

**기각한 안**: "창이 가려지면 스트림 중지"는 코덱스 반대로 채택하지 않았다 — 사용자가 중지를 요청한 게 아니고, 캡처 detach/reselect/키프레임 churn이라는 과거 피커 freeze 부작용을 재도입하며, 디코드를 버리면 H.264 참조 체인이 깨져 복귀 시 디코더 리셋+IDR이 필요하다.

**조사 중 자체 정정 2건**: (1) "occlusion으로 Present가 멈췄다"는 틀렸다 — `DXGI_STATUS_OCCLUDED`는 이미 성공 처리 중이고 `d3dPresentFail=0`이다. (2) "`paintCoalesced` 증가 = WM_PAINT 실행 중"도 틀렸다 — 그 카운터는 **수신 스레드에서도** 증가하며, 오히려 래치 고착의 증거였다.
