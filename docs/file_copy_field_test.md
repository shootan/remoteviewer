# 파일 복사(네트워크) — 사용자 실기 1회 안내

t-zdmsd4gb r1 4단계. 자동 시험이 증명하지 못한 부분만 사람이 **한 번** 확인한다: 실제 설치본에서
**제품 도우미(GNLinkClipHelper.exe)가 뜨는지**와 **탐색기 Ctrl+C / Ctrl+V 가 양방향으로 되는지**.

## 이미 자동으로 확인된 것 (다시 볼 필요 없음)
- 바이트 정확성·Seek·중복 Read·빈 파일·다중 파일, 원본 교체/변경 거절, 소비자 사망, 권한 철회,
  stale 응답, stall, 이미지 선점 — 루프백 + 프록시 net e2e(시험 빌드, 도우미를 같은 사용자로).
- 제품 창의 전송 바(제공·보내는 중·취소·완료)와 취소 버튼 클릭 — 제품 WndProc, 시험 host.
- 설치 파일이 도우미를 싣는지 — `gnlink_check_installer_payload.ps1` 10/10(로컬 빌드).

## 자동으로 증명 못 한 것 = 이번 실기의 대상
1. **Host**: 관리자(`requireAdministrator`)로 도는 GNLinkStream 이 **로그인 사용자 토큰(연결 토큰)**으로
   도우미를 띄우는 것. 시험 빌드는 비관리자라 이 경로를 못 탄다. 실패하면 High/SYSTEM 으로
   대신 띄우지 않고 **거절**하는 것이 정상 동작이다.
2. 실제 **탐색기**가 원격 파일 목록을 받아 붙여넣는 것(시험은 셸 소비자 흉내 + 실제 IStream).
3. 실제 회선(원격 PC)에서의 속도·바 표시.

## 준비
- 두 PC 모두 이 기능이 든 버전 설치(설치 시 UAC 1회 — 이번 실기에서 사람이 하는 승격은 이것뿐이어야 한다).
  설치 폴더에 `GNLinkClipHelper.exe` 가 있는지 확인.
  ⚠️ **업데이트로 올릴 때 주의**: 이전 버전의 업데이터는 자기가 아는 파일만 교체한다. 그래서
  이 기능이 **처음 들어간 버전으로의 업데이트 한 번으로는 도우미가 설치되지 않을 수 있다**
  (업데이터가 새 파일 목록을 가진 채 교체되고, 그다음 업데이트부터 들어간다). 실기는 **설치 파일로**
  설치하거나, 설치 폴더에 도우미가 있는지 먼저 확인한다.
- 클립보드 동기화가 켜져 있어야 한다(파일은 그 스위치를 따른다). `REMOTE60_CLIPBOARD_FILES=0` 이
  설정돼 있지 않아야 한다.
- 시험 파일: 작은 파일 몇 개 + **수백 MB 파일 하나**(진행·취소를 보기 위해). **폴더·바로가기·잘라내기는
  이번 범위가 아니다**(폴더가 섞이면 제공되지 않는 것이 정상).

## 절차 (뷰어 PC = 내 PC, 호스트 = 원격 PC)
| # | 할 일 | 기대 결과 |
|---|---|---|
| 1 | 원격 PC에 접속 | 평소대로 화면이 나온다 |
| 2 | **내 PC** 탐색기에서 작은 파일 2개 선택 → Ctrl+C | 뷰어 바: "복사한 파일 2개를 원격 PC에서 붙여넣을 수 있습니다" (아직 보낸 것 아님) |
| 3 | **원격 화면** 안 탐색기의 폴더에서 Ctrl+V | 바: "원격 PC로 파일 2개 보내는 중 …%" → "원격 PC에서 파일 2개 붙여넣기 완료 (… MB, … 초)". 원격 폴더에 두 파일, 내용 동일 |
| 4 | 내 PC에서 큰 파일 Ctrl+C → 원격에서 Ctrl+V → 진행 중 바의 **취소** 클릭 | "취소하는 중… (상대 PC의 확인을 기다립니다)" → "파일 붙여넣기를 취소했습니다 — 받는 쪽에 일부만 저장된 파일이 남았을 수 있습니다". 원격 탐색기도 복사를 멈춘다 |
| 5 | **원격 화면** 안 탐색기에서 작은 파일 2개 Ctrl+C | 바: "원격 PC에서 복사한 파일 2개를 이 PC에 붙여넣을 수 있습니다" |
| 6 | **내 PC** 탐색기 폴더에서 Ctrl+V | "원격 PC에서 파일 2개 받는 중 …%" → "파일 2개 붙여넣기 완료". 내용 동일 |
| 7 | 원격에서 큰 파일 Ctrl+C → 내 PC에서 Ctrl+V → 취소 | 4 와 같은 순서의 문구 |
| 8 | (선택) 2 의 파일을 Ctrl+C 한 뒤 원본을 내 PC에서 다른 내용으로 저장 → 원격에서 Ctrl+V | 바이트를 보내기 전에 거절: "원본 파일이 복사한 뒤 바뀌어 붙여넣지 못했습니다" |

## 결과와 함께 볼 로그
- **호스트(원격 PC)**: GNLinkStream 출력에서 `[file-copy]` 줄. 도우미 기동 실패면
  `host copy not offered: helper unavailable (<이유>)` 또는 paste 거절 줄에 이유가 남는다
  (예: `medium-launch-refused-caller-elevated`, 연결 토큰 없음). 로그는 NAS 디렉터리 서버의 해당 기기
  스트림에서 먼저 보고, 없으면 원격 PC 로컬 로그를 본다.
- **뷰어(내 PC)**: `viewer.log` 의 `[file-copy]` 줄 — 제공·paste 시작/끝(state/reason)·검증 실패.
- 로그에는 **원본 전체 경로를 남기지 않는다**(파일 이름·개수·크기만). 전체 경로가 보이면 그 자체가 결함이다.
- 실패 시 알려 줄 것: 몇 번 단계인지, 바 문구 그대로, 두 PC의 시각.

## 알고 쓰는 제약
- **평문(A3)**: 파일 **내용과 이름·크기** 가 텍스트·이미지 클립보드와 똑같이 **암호화되지 않은 채** 회선을
  지난다. 청크 SHA-256 은 전송 오류 검출용이지 상대 인증·암호화가 아니다. 통신 암호화는 별도 결정 항목이다.
- **속도**: 지금 제어 채널은 한 번에 메시지 하나만 오간다(stop-and-wait). 왕복 40 ms 회선에서 대략
  4 Mbps 가 상한이라 수백 MB 는 수 분이 걸릴 수 있다. 창 방식 채널·청크 확대는 Codex 결정 대기다.
- 영상이 밀릴 때 파일 송신을 미루는 정책(D1)은 아직 없다(Codex 결정 대기) — 큰 파일 전송 중 화면이
  느려질 수 있다.
- 이미지 붙여넣기 중에 파일 붙여넣기를 하면 이미지를 멈추고 파일을 먼저 보낸다. 멈춘 이미지는
  조건이 맞으면 처음부터 다시 제공된다.
