## 3. 지연 분리 (가능한 범위)

호스트 내부 — **모두 표본**이며 서로 다른 프레임의 표본을 더해 구간 합을 만들지 않는다. wire 표본 = 키프레임 또는 송신 간격 >1.5×목표인 프레임(`host_encoded_sender.cpp:218`); user-feedback 표본 = `pipeUs`(= `hdr.sendQpcUs − hdr.captureQpcUs`; `hdr.sendQpcUs` 는 주 스레드가 **입큐 전**에 찍는 송신 준비 시각(`host_stage_encode_send_h264_au.cpp:268`)이고 실제 와이어 시각은 sender 스레드가 `item.udpHdr.sendQpcUs` 에만 다시 쓴다(`host_encoded_sender.cpp:175`) → pipeUs = **AU capture stamp → 주 스레드 입큐 전 송신 준비 시각**, 인코더 보유 포함, sender 큐 대기·실제 UDP 송신 제외, capture stamp 는 보정된 값일 수 있음; `…h264_au.cpp:563`) 가 경고 임계 이상인 AU 만, 1초 rate-limit. 비동기 인코더에서는 user-feedback 의 입력 단계 필드(captureUnmapWait 등)와 AU 헤더의 capture 가 서로 다른 프레임일 수 있어 단계별 합산에 쓰지 않는다.
