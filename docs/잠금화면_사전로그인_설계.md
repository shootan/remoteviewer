# 잠금화면 / 로그인 전 원격 접속 설계

작성일: 2026-07-27
상태: 설계 (미구현)

## 1) 왜 지금은 안 되는가

이 PC의 실제 세션 구조를 측정한 결과다.

```
SESSIONNAME     USERNAME    ID   STATE
services                     0   Disc     <- 서비스 전용 세션
                shotan       2   Disc     <- 사용자 RDP 세션 (호스트가 여기서 실행됨)
console                      9   Conn     <- 물리 화면. 로그인 사용자 없음 = 잠금/로그인 화면
rdp-tcp                  65536   Listen
```

`WTSGetActiveConsoleSessionId() = 9`.

여기서 세 가지 사실이 나온다.

1. **호스트는 세션 2(RDP 세션)에서 돌고 있다.** 즉 캡처 대상이 물리 화면이 아니라 RDP 가상 화면이다.
2. **물리 화면(세션 9)은 로그인 화면 상태이고, 이걸 캡처하는 주체가 없다.** 그래서 사용자가 본 대로 접근이 안 된다.
3. **RDP 연결을 끊으면 세션 2는 disconnected가 되고 데스크톱 합성이 멈춘다.** 이때 DXGI Desktop Duplication이 출력을 못 찾는다 — `docs/history.md:2492`에 이미 기록된 `dxgi_no_output_found -> WGC ShellWindow fallback` 증상이 바로 이것이다.

재부팅 후에는 세션 2 자체가 없다. 사용자가 로그인해야 생긴다. 그래서 **현재 구조로는 재부팅 후 접속이 원리적으로 불가능하다.**

## 2) 목표

- 부팅 직후, 아무도 로그인하지 않은 상태에서 접속 가능
- 잠금화면/로그인 화면이 그대로 보이고, 거기서 비밀번호를 입력해 로그인 가능
- UAC 승격 프롬프트(보안 데스크톱)도 보이고 조작 가능
- 로그인 후에는 자동으로 사용자 데스크톱으로 전환

## 3) 구조

Windows는 서비스(세션 0)에서 사용자 데스크톱을 직접 캡처할 수 없다(Session 0 Isolation).
표준 해법은 **서비스 + 세션 에이전트** 2단 구조다. TeamViewer/AnyDesk/OSLink 전부 이 형태다.

```
[remote60-host-svc]  서비스, 세션 0, LocalSystem, 자동 시작
   │   부팅 시 사용자 로그인 없이 기동
   │   네트워크 리스너를 직접 들지 않고 에이전트를 감독만 한다
   │
   │   SERVICE_CONTROL_SESSIONCHANGE + WTSGetActiveConsoleSessionId() 로
   │   콘솔 세션 변화를 추적
   │
   └── CreateProcessAsUser(SYSTEM 토큰, 콘솔 세션, desktop="WinSta0\\Default")
        │
        ▼
   [remote60-host-agent]  콘솔 세션, SYSTEM 권한, 대화형
        │   기존 host 코드가 거의 그대로 들어간다
        │
        ├─ 입력 데스크톱 추적: OpenInputDesktop() -> SetThreadDesktop()
        │    Default(로그인 후) <-> Winlogon(잠금/로그인/UAC) 전환을 따라간다
        │
        ├─ 캡처: 데스크톱 전환 시마다 DXGI Duplication 재생성
        │
        └─ 입력: SendInput (현재 스레드가 붙은 데스크톱에 주입)
```

## 4) 반드시 지켜야 할 기술 제약

### 4.1 잠금화면에서는 WGC를 쓸 수 없다

`Windows.Graphics.Capture`는 WinRT API로, Winlogon 보안 데스크톱에서는 동작하지 않는다.
**보안 데스크톱 캡처는 DXGI Desktop Duplication만 가능하다.**

현재 기본 백엔드는 WGC이므로(`REMOTE60_DESKTOP_CAPTURE_BACKEND` 미설정 시 WGC),
에이전트는 **현재 입력 데스크톱이 Winlogon이면 DXGI로 강제 전환**해야 한다.
다행히 DXGI 백엔드는 `apps/host/src/capture_backend_dxgi.cpp`에 이미 있다.

### 4.2 데스크톱이 바뀌면 캡처를 재생성해야 한다 — 현재 폴백 정책은 반대로 동작한다

Duplication 객체는 데스크톱에 묶인다. 잠금/해제/UAC 순간 `DXGI_ERROR_ACCESS_LOST`가 난다.

문제는 현재 코드가 이 신호를 **정확히 잘못된 방향으로 처리**한다는 점이다.
`apps/host/src/capture_backend_dxgi.cpp:170-181`에서 ACCESS_LOST/DENIED를 받으면
`recreate_duplication`을 **한 번만** 시도하는데, 그 함수(`:138-155`)는
**같은 `d3dDevice`와 같은 `HMONITOR`를 그대로 재사용**한다. 데스크톱을 다시 붙지 않는다.
따라서 보안 데스크톱 전환 시 재생성은 실패하고, 실패하면 `request_fallback`이 호출되어
DXGI 스레드가 종료되고 **WGC로 영구 강등**된다(`realtime_runtime.cpp:2954-2966`).
그런데 WGC는 보안 데스크톱을 아예 볼 수 없으므로, 결과적으로 잠금화면에서 화면이 완전히 죽는다.

즉 S2는 "데스크톱 추적 추가"만으로 끝나지 않고 **폴백 정책 자체를 바꿔야 한다.**

```
현재 입력 데스크톱 이름 폴링(약 200ms) 또는 세션 알림 수신
  -> 이름이 바뀌었으면
       SetThreadDesktop(새 데스크톱)
       D3D 디바이스 + Duplication 전부 재생성 (같은 디바이스 재사용 금지)
       인코더 키프레임 강제

ACCESS_LOST 처리 변경:
  - 데스크톱 전환이 원인일 수 있으므로 즉시 WGC 강등하지 말 것
  - 재부착 + 완전 재생성을 백오프로 N회 재시도
  - 보안 데스크톱에 있는 동안에는 WGC 폴백 자체를 금지
```

참고로 DXGI 백엔드는 `landscapeOnly = true`로 설정되어 있어(`realtime_runtime.cpp:1848`)
세로 방향 출력을 `rotation_unsupported`로 거부한다. 로그인 화면이 세로 모니터인 환경에서는
이 조건도 완화해야 한다.

### 4.3 잠금화면 입력은 PostMessage가 아니라 SendInput

현재 window 모드 입력은 대상 HWND에 `PostMessageW`를 보낸다.
Winlogon 데스크톱의 창(LogonUI.exe)은 Default 데스크톱에서 열거되지 않으므로 이 경로는 동작하지 않는다.
**보안 데스크톱에서는 desktop 모드(SetCursorPos/SendInput)만 유효하다.** 이미 구현되어 있는 경로다.

### 4.4 Ctrl+Alt+Del은 SendInput으로 만들 수 없다

커널이 가로채는 보안 주의 시퀀스(SAS)다. `sas.dll`의 `SendSAS()`를 SYSTEM 서비스에서 호출해야 한다.

- 이 PC에 `C:\Windows\System32\sas.dll` 존재 확인됨
- `SoftwareSASGeneration` 미설정 = 기본값이며, 서비스의 SendSAS 호출은 허용된다
- `DisableCAD` 미설정. Windows 11 기본 설치에서는 로그인 시 Ctrl+Alt+Del이 보통 요구되지 않으므로
  필수는 아니지만, 뷰어에 "Ctrl+Alt+Del" 버튼은 있어야 한다

### 4.5 RDP 세션과 콘솔 세션은 다른 화면이다 — 운영상 중요

에이전트를 **콘솔 세션**에 붙이면 재부팅 후에도 뜨고 잠금화면이 보인다. 이게 목표에 맞다.
대신 사용자가 동시에 RDP로 접속해 있으면 **콘솔은 잠금화면 상태**이므로 안드로이드에는 잠금화면이 보인다.
RDP 세션 화면이 보고 싶다면 그건 별개의 선택지이며, 재부팅 생존과 양립하지 않는다.

권장: 기본은 콘솔 세션 추적. 필요하면 "활성 사용자 세션 우선" 옵션을 따로 둔다.

## 5) 보안: 이 기능과 함께 반드시 들어가야 할 것

현재 프로토콜에는 **인증이 전혀 없다.**

- `apps/native_poc/src/native_video_host_main.cpp:2469,2503,2643` — 모두 `INADDR_ANY` 바인드
- 핸드셰이크에 비밀번호/토큰/페어링 개념 없음. 포트만 알면 누구나 접속해 화면을 보고 입력을 넣을 수 있다

지금까지는 "로그인한 사용자가 직접 켠 프로세스"라 노출 범위가 제한적이었다.
서비스로 만들어 로그인 전부터 상시 실행하면, **인증 없는 LAN 피어가 로그인 화면의 PC를 상시 조작할 수 있게 된다.**
이건 기능 결함이 아니라 설계 공백이며, 잠금화면 지원과 **같은 릴리스에 인증이 함께 들어가야 한다.**

최소 요구사항:
1. 최초 실행 시 기기 ID + 랜덤 비밀번호 생성, 호스트 화면에 표시
2. 클라이언트 접속 시 challenge-response (평문 비밀번호 전송 금지)
3. 실패 시도 지수 백오프
4. 기본 바인드를 LAN 대역으로 제한하거나, 최소한 접속 시 호스트에서 승인
5. 연결/해제/입력 주입 이벤트 감사 로그

## 5.5) 코드 감사 결과 — 현재 보유한 building block

전 저장소(C++/PowerShell 전체)를 검색한 결과다.

| 잠금화면/사전 로그인에 필요한 요소 | 현재 존재 여부 |
|---|---|
| Windows 서비스 (세션 0) | 없음 |
| `WTSGetActiveConsoleSessionId` / `WTSQueryUserToken` | 없음 |
| `CreateProcessAsUser` (콘솔 세션 주입) | 없음 |
| `OpenInputDesktop` / `SetThreadDesktop` / `OpenDesktop("Winlogon")` | 없음 |
| 세션 변경 알림 (`WTSRegisterSessionNotification`) | 없음 |
| 영구 자동 시작 (서비스/작업 스케줄러/Run 키/시작 폴더) | 없음 |
| 승격 매니페스트 (`requireAdministrator` / `uiAccess`) | 없음 — `asInvoker` |
| 데스크톱 전환 후 재부착 | 없음 (§4.2 참조) |
| DXGI Desktop Duplication 백엔드 | **있음** (`capture_backend_dxgi.cpp`) |
| SendInput/SetCursorPos 기반 desktop 모드 입력 | **있음** (`realtime_runtime.cpp:800-1208`) |

즉 **캡처 엔진과 입력 주입이라는 두 무거운 조각은 이미 있고, 없는 것은 전부 세션/데스크톱 배관이다.**
새 렌더링·인코딩 코드를 쓸 일은 없다는 뜻이라, 난이도보다는 분량의 문제다.

기존 런처(`automation/*.ps1`)는 전부 `Start-Process`로 현재 대화형 세션에 띄우기만 하며,
승격도 영속화도 하지 않는다. 세션이 끝나면 같이 죽는다.

## 6) 작업 순서

| 단계 | 내용 | 규모 |
|---|---|---|
| S1 | 인증(페어링 + challenge-response) 추가 | 중 |
| S2 | 입력 데스크톱 추적 + 전환 시 DXGI 재생성 (기존 host에 추가, 콘솔에서 수동 실행으로 검증) | 중 |
| S3 | 서비스 + 세션 에이전트 분리, CreateProcessAsUser로 콘솔 세션 주입 | 대 |
| S4 | SendSAS 기반 Ctrl+Alt+Del, 뷰어 버튼 | 소 |
| S5 | 설치 프로그램(서비스 등록, 방화벽 규칙, 자동 시작) | 중 |

S2는 단독으로도 의미가 있다. 관리자 권한 PowerShell에서 `PsExec -s -x` 같은 방식으로
SYSTEM+콘솔 세션에 수동 기동해 잠금화면 캡처가 되는지 먼저 증명할 수 있고,
그게 되면 S3의 나머지는 배관 작업이다.
