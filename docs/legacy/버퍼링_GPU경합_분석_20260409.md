# 버퍼링 악화 원인 분석 — D3D11 단일 디바이스 경합
분석일: 2026-04-09

---

## 현상

Host 프로세스 실행 시 스트리밍 버퍼링이 체감 수준으로 악화된다.

---

## 원인

`native_video_host_main.cpp:2696-2702`에서 D3D11 디바이스를 1개만 생성하고, 이를 캡처·스케일링·인코딩 3개 경로가 공유한다.

```
D3D11CreateDevice(...)  →  d3d (단일 디바이스)
                            ├── WGC 캡처 콜백 (CopyResource + Map + memcpy)
                            ├── GpuBgraScaler  (VideoProcessorBlt)
                            └── MFT H264 인코더 (HW encode)
```

D3D11 DeviceContext는 스레드 안전하지 않으므로 `d3dContextMu` 뮤텍스로 직렬화된다.

### 경합 지점

| 사용처 | 위치 | 작업 | 뮤텍스 점유 시간 |
|--------|------|------|-----------------|
| WGC 캡처 콜백 | `native_video_host_main.cpp:3070-3080` | `CopyResource` → `Map` → per-row memcpy → `Unmap` | **가장 김** (1080p 기준 ~8MB 복사) |
| GPU 스케일러 | `native_video_host_main.cpp:2716`, `gpuScaler.scale()` | `VideoProcessorBlt` | 중간 |
| MFT 인코더 | `native_video_host_main.cpp:2711`, `encoder.set_d3d11_device()` | HW 인코딩 내부 GPU 접근 | 중간 |

### 병목 메커니즘

1. WGC `FrameArrived` 콜백(FreeThreaded 풀 스레드)이 `d3dContextMu`를 잡고 `CopyResource` + `Map` + **per-row memcpy 8MB** 수행
2. 이 구간 동안 인코딩 스레드의 GPU 스케일러(`VideoProcessorBlt`)가 뮤텍스 대기로 블로킹
3. 반대로 인코딩 중 캡처 콜백이 도착하면 캡처도 블로킹
4. 결과: 캡처 → 인코드 → 전송 파이프라인이 직렬화되어 프레임 지연 누적

### 추가 부하 요인

- 캡처 콜백 내 `std::make_shared<std::vector<uint8_t>>(stride * frameH)` — 프레임마다 ~8MB 힙 할당/해제 (`native_video_host_main.cpp:3068`)
- CPU 기반 `bgra_to_nv12` 변환 (`mf_h264_codec.cpp:857`) — GPU에서 CPU로 읽어온 데이터를 다시 CPU에서 변환
- CPU fallback 스케일링 `resize_bgra_bilinear` — GPU 스케일러 실패 시 전량 CPU 처리

## 개선안

### 안 (C) — 뮤텍스 구간 축소 [단기, 최소 변경]

**대상**: `native_video_host_main.cpp:3068-3081`

**현재**:
```
lock(d3dContextMu)
  CopyResource(staging, src)
  Map(staging)
  for (y = 0..H) memcpy(dst, src, stride)  ← 8MB, 뮤텍스 안
  Unmap(staging)
unlock
```

**개선**:
```
lock(d3dContextMu)
  CopyResource(staging, src)
unlock

lock(d3dContextMu)
  Map(staging, D3D11_MAP_READ)
unlock
  for (y = 0..H) memcpy(dst, mapped, stride)  ← 뮤텍스 밖
lock(d3dContextMu)
  Unmap(staging)
unlock
```

- `Map`은 GPU → CPU 전송 완료 대기 후 포인터를 반환하므로, 이후 memcpy는 순수 CPU 작업
- memcpy 구간(~8MB)을 뮤텍스 밖으로 이동하면 GPU 스케일러/인코더 블로킹 시간 대폭 감소
- **주의**: `Map`~`Unmap` 사이에 다른 스레드가 동일 staging 텍스처를 건드리지 않아야 함. 현재 staging은 캡처 콜백 전용이므로 안전.

**예상 효과**: 뮤텍스 점유 시간 ~80% 감소 (8MB memcpy 시간 제거)

---

### 안 (B) — D3D 디바이스 분리 [중기]

**변경 범위**: 디바이스 생성부 + GPU 스케일러 + 인코더 초기화

**구조**:
```
D3D11CreateDevice → d3dCapture  (캡처 전용)
D3D11CreateDevice → d3dEncode   (스케일링 + 인코딩 전용)

WGC 캡처: d3dCapture로 CopyResource + Map
GPU 스케일: d3dEncode로 VideoProcessorBlt
MFT 인코더: d3dEncode로 HW encode
텍스처 공유: IDXGIResource::CreateSharedHandle → OpenSharedResource
```

- 캡처와 인코딩이 별도 디바이스/컨텍스트를 사용하므로 뮤텍스 경합 완전 해소
- 텍스처 공유 오버헤드는 미미 (GPU 내부 복사)
- GPU 메모리 약간 증가 (디바이스 2개)

**예상 효과**: 캡처-인코딩 간 뮤텍스 경합 제거, 파이프라인 병렬화

---

### 안 (A) — Zero-copy GPU 파이프라인 [장기, 최대 효과]

**변경 범위**: 캡처 콜백 → 스케일러 → NV12 변환 → 인코더 전체 경로

**현재 경로**:
```
GPU 텍스처 → CopyResource → Map → CPU memcpy 8MB → CPU bgra_to_nv12 → MFT encode
```

**개선 경로**:
```
GPU 텍스처 → (GPU) VideoProcessorBlt 스케일 → (GPU) NV12 변환 → MFT encode (GPU 텍스처 입력)
                     CPU readback 제거
```

**핵심 변경사항**:
1. `FrameArrived` 콜백에서 CPU readback(`Map`/memcpy) 제거 — 캡처 텍스처를 GPU에 유지
2. `GpuBgraScaler`가 캡처 텍스처를 직접 수신 → BGRA→NV12 변환도 GPU 셰이더로 수행
3. MFT 인코더에 `MFT_MESSAGE_SET_D3D_MANAGER`로 등록된 D3D Device Manager를 통해 NV12 텍스처 직접 입력
4. Frame gating용 변경량 판단(`estimate_bgra_change_permille`)만 별도 경량 GPU readback 또는 compute shader로 대체

**제거되는 부하**:
- 프레임당 ~8MB CPU memcpy (캡처 readback)
- 프레임당 ~12MB CPU bgra_to_nv12 변환 (1080p NV12 = ~3MB, 입력 BGRA = ~8MB)
- 프레임당 힙 할당/해제 (`std::make_shared<vector<uint8_t>>`)

**예상 효과**: 프레임당 CPU 부하 ~20MB 메모리 연산 제거, GPU 파이프라인 완전 병렬화
