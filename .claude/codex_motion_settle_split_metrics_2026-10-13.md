### 필요한 증거

1. **독립 빌드 + 기존 28개 반례 재현:** 고정 M4 candidate에서 통과, d84001a의 옛 창 동작 또는 동일 범위 rollback에서 가짜1fps/강등 assertion 실패. helper→scheduler→host policy 시험임을 정확히 표시한다. 60fps case의 host activeFps가 테스트 내30으로 고정된 한계도 보완하거나, 그 case는 보고 cadence만 검증했다는 범위를 유지한다.
2. **실제 product receiver 경로 1묶음:** `VideoReceiver → flush_stats_if_due → 실제 metrics snapshot/scheduler → control 전송/host 수신 → ABR`를 사용한다. 격리 Host/ViewerRig 또는 실제 Viewer 시험 빌드로 충분하며 production 함수를 시험에서 복제하면 안 된다. 짧은 실제 공백(예30초)과 재개를 실행하고 180/190초는 결정적 시계 시험으로 보강할 수 있다. 프레임 수/보고 elapsed·publish 시각/제어 수신/ABR profile을 연결한다. 옛 코드와 candidate가 같은 장면을 받았는지도 확인한다.
3. 행동 assertion은 ‘보고 없음’이 아니라 **복귀 후 올바른30/60fps 보고가 다시 생기고, 보고 폭주·가짜1fps·가짜 stale-active 강등이 없으며, 화면의 새 내용도 전달됨**이다. picker/무프레임 대기·1Hz 정지 refresh 후 재개, reconnect/selection 경계를 포함한다. 새로 도착하는 decoder output이 없는 상황과 정상 공백을 구별한다.
4. 기존 실제 장애 판단 보존: 송신30 대비 decode2, 도착3, 보고 중단, 3초에 한 장만 도착, 지속 지연/손실의 강등·회복을 기존 ABR/receiver 시험으로 확인한다. 전혀 보고한 적 없는 peer와 보고하다 멈춘 peer의 구분도 유지한다. UDP/TCP가 같은 통계 helper를 소비하는 배선과 rate 단위(0.5/1/1.9/2초 경계)를 확인한다. 전체 새 GPU 성능 행렬이나 추가 Home PC 실행은 이 통계 전용 릴리스의 필수조건으로 만들지 않는다.
5. main 통합 후 영향 회귀: viewer stats window, shared control scheduler/ABR, 실제 receiver/recovery/FrameGate·재접속, 관련 build gate. 이후 고정 version build→패키징/서명·변조 거부→NAS 게시→외부 artifact 전체 hash·manifest/version 확인→dist/기록. 검증용 명시 OK와 고정 source/build hash를 Codex에 한 묶음으로 보내 최종 확인한다. 통상 게시·push는 현재 사용자 승인 범위와 저장소 절차에 따르며 이 문서로 새로운 권한을 부여하지 않는다.

**1차 완료 문구는 ‘긴 무프레임 뒤 잘못된1fps 보고와 그에 따른 불필요한 ABR 강등 보수’로 한정한다.** 글자 정제/움직임 시작 문제 전체가 해결됐다고 보고하지 않는다. 해당 task의 M1 실험은 별도 진행 상태로 유지한다.

## 3. 2차 구성: floor 제거 뒤도 무회귀를 입증해야 한다

- 기준은 **M4만 적용한 출하/동등 소스**다. 8b51bdf의 계측 Host를 쓰면 제품 동등 차이를 적고, 신규 baseline/candidate가 같은 Viewer·control·codec/캡처 조건을 사용하게 한다.
- 다음 순서의 작은 paired 대조로 한 구성을 고른다: ① 정제 off ② M1만(최신 내용 재제출, 먼저8입력/1초 이내) ③ M1+보수적 F(20/24 또는16의 입증된 값) ④ 필요할 때만 추가 입력/간격/byte 예산 조정. **floor=0·M2=0 공통**. 4.5M의 −floor 결과를 1.5M에 일반화하지 않는다. 먼저 1.5M typechar/scroll1s/stopstart/restart에서 정제off/on과Foff/on을 분리한다.
- M1의 ‘마지막 실제 내용이 admission에 skip돼도 신속히 전달’은 정제 열차와 구별한다. 최신 내용 전달을 정제 quota 소진·quiet의 긴 마감·오래된 episode에 종속시키지 않는다. 그 뒤의 추가 품질 프레임은 취소 가능한 낮은 우선순위 작업이다.
- **R에 비례한 바이트 상한만으로 응답성을 보장하지 않는다.** 후보는 이미25% 예산인데도 저rate에서 지연됐다. 미완료 정제 AU/실제 wire tail·MFT 입력·토큰 부채와 새 입력의 관계를 본다. 새 내용/키 의무가 생기면 추가 정제 제출을 즉시 멈추고, 동일 참조 체인의 이미 생성된 AU를 임의 폐기하지 않는다. 작은 입력 묶음/송신 여유에서만 추가하는 방식과66/100ms 간격을 비교한다. 저rate에서 추가 정제를 줄이거나 꺼야 하면 그 셀의 개선 범위를 정확히 기록한다.
- F가 없는 구성이 더 좋은 장면에는 F를 강제하지 않는다. MinQP는 이번 출하 후보에서 제외하고, B/EncodeQP는 계속 격리 대조 범위만 허용한다. 새 제어 레버를 계속 덧붙이기 전에 이 단순한 구성에서 개선/비용을 고정한다. ‘유일한 후보’라는 명칭은 쓰지 않는다.
- 선택 전에는 짧은 소수 장면/셀에서 귀속을 확인하고, **하나의 구성만** 20episode×3회 및 AMD/NVIDIA·캡처 경로 검증으로 확대한다. branch에 남은 실험 코드가 출하 환경에서 켜지는지 별도 확인한다.

## 4. 화질 지표의 새 역할과 기준 고정

`ref−1dB`에서 p95가 전부 >9초인 것은 **가장 높은 장기 품질에 거의 도달하지 못했다는 유효한 결과**다. 판별력이 전혀 없다는 뜻은 아니다. 다만 사용자 요구인 ‘스크롤 후 빨리 읽을 수 있음’과 near-plateau 수렴을 같은 완료 조건으로 둔 것은 너무 강한 대용 지표였으므로, 아래 역할 분리에 동의한다.

### 4.1 주 완료 지표: 읽을 수 있는 품질까지의 시간

- 셀/장면별 **`Q_read`(읽기 품질 anchor)**를 새 후보 비교 전에 고정한다. 원본과 같은 크기/폰트/색변환/ROI에서, 장기 정지의 명확히 읽히는 화면 및 알려진 흐림 화면을 비교해 검증용이 실제 작은 한글/영문 글자·획 구분을 확인한다. 원본/anchor PNG와 hash, 선택 이유를 보존한다. 그 anchor에 대응하는 glyph PSNR/edge 오차를 수치 기준으로 사용한다.
- 모든 장면에 ‘45dB면 읽힘’ 같은 보편 상수를 정하지 않는다. **새 후보의 낮은 품질을 보고 Q_read를 낮추지 않는다.** r3 결과는 개발/교정 자료로 사용할 수 있지만 anchor를 고정한 뒤 새 repeat/내용 seed로 검증한다. 비교 중 reference를 계속 높은 후보 calibration로 갈아끼우지 않는다.
- `T_read` = 올바른 final-content 화면이 도착하고 Q_read를 충족해500ms 유지되는 첫 시각. 기존 시간 목표는 유지한다: 4.5/6M p95≤1초·개별 episode≤2초, 1.5M p95≤1.5초·개별≤2초. 못 읽히거나 최종 화면이 안 오면 실패/censored이며 INVALID로 빼지 않는다. 자동 수치 통과만으로 끝내지 않고 각 셀의 worst/p10/median crop을 독립 확인한다.
- Q_read를 충분히 객관화하지 못하면 **고정시점 품질 개선**까지만 주장하고 ‘글자 복구 완료’ 승인은 내리지 않는다. 사용자에게 여러 번 새 숫자를 고르게 하지 말고 기존 증상/화면을 근거로 검증용이 calibration을 준비한다.

### 4.2 주 비교 지표: 고정 시점 화질과 최종 내용 도착

- @0.5/1/2초(저rate 판정용1.5초 포함)의 glyph PSNR **절대값·동일 baseline 대비 Δ·p10/p50/p95**, T_final을 보고한다. 현재 summary의 중앙값만으로 느리거나 흐린 꼬리를 숨기지 않는다. source 그림이 다른 episode를 단순 dB 평균으로 섞지 않는다.
- 실제로 흐렸던 사전 지정 문제 장면에서는 **@1초 중앙값 +3dB 이상**을 실질 개선 목표로 사용한다(이미 Q_read에 도달한 baseline 장면에는 이 증가를 억지로 요구하지 않음). 낮은 분위도 좋아져야 하며, 다른 장면의 @0.5/1/2초 p10이 baseline보다1dB 이상 나빠지거나 명확한 글자 획 손실이 생기면 회귀로 본다. 이 보조 차이 기준은 T_read/응답성 실패를 덮지 못한다.
- baseline/candidate가 같은 물리 크기여야 한다. 720p ladder와1080p의 PSNR는 별도 셀, 손실/decoder 오류/누락은 별도 축이다. 가독성 확보를 몰래 해상도·fps 감소로 달성하지 않는다.

### 4.3 장기 품질은 유지하는 보조 축

- 기존 고정 `ref−1dB` 도달 시간·도달률·censored를 계속 보고한다. `ref−3dB`는 사전에 고정한 **추가** 도달률/시간 지표로 허용한다. 1dB 결과를3dB로 덮어쓰거나, 이를 예전 gate 통과라고 부르지 않는다.
- 6M noise처럼 reference가 미확정이면 해당 도달률은 N/A이고, 원본 기반 고정시점 품질·가독성 anchor는 별도로 다룬다. ‘최고 calibration의 plateau에 못 미침’과 ‘문자가 안 읽힘’을 구분하며 장기 품질이 낮게 고착하는 구성은 관찰을 남긴다.

## 5. 응답성은 품질과 독립된 차단 조건

- floor 제거만으로 무회귀를 선언하지 않는다. first-reaction p95·첫1초 실제 서로 다른 내용의 전달량·최대gap·T_final을 같은 precondition에서 검증한다. 4.5M typechar177→259, stopstart115→248, 저rate typechar131→350/scroll67→414 같은 **신규 악화는 계속 차단**한다.
- baseline이 기존 절대 목표를 통과한 셀에서는 candidate도 통과해야 한다. 아울러 p95 first-reaction/T_final의 baseline 대비 증가를 **실제 한 프레임 기간 이내(최대33ms)**로 제한하고 3회 반복에서 일관된 악화를 따로 검사한다. renderer/원본 자체 gap이거나 이미 알려진 GOP tail은 양쪽의 event/IDR/실제 송신 타임라인으로 귀속한다.
- baseline부터 절대 gap/첫 반응 목표를 못 지킨 셀은 그 사실을 유지한다. **동일 원인인 기존 한계에 한해서** 새 회귀 없음 + 품질 개선으로 부분 개선 후보를 판단할 수 있지만, 새로 생긴 지연을 기존 실패에 묻지 않는다. 최대gap과 실패 episode는 전부 보고하고, 느린 장면/정기IDR을 사후로 표본에서 제거하지 않는다. 이 예외를 쓰는 릴리스는 기존 한계가 남은 범위를 명시한다.
- wire cap/FEC/NACK·epoch/키 의무·bounded queue·정지/선택·캡처 callback 수명 조건은 그대로다. 새 freeze, 장시간 누적, 새 움직임이 정제에 가려짐은 숫자 평균과 무관하게 실패다.

## 6. 다음 담당과 보고

검증용은 **M4 분리 후보·실제 경로/독립 근거 → 최종 확인 → 1차 릴리스**를 먼저 잇는다. 2차 연구가1차를 막지 않으며, M4 게시를 motion-settle 전체 task 완료로 취급하지 않는다. 작업용1의 다음 M1 지시서는 floor/M2 제외·저rate 귀속·새 anchor/지표를 반영한 한 문서로 교체한다. 같은 범위 설정 비교마다 승인 왕복은 필요 없다.

M4에는 GPU 화질 행렬을 새로 요구하지 않는다. M1은 실제 field의 AMD DXGI 경로를 아직 검사하지 못한 한계를 유지하고 격리/사용자 허용 범위에서 증거를 확보한다. NVIDIA/현장 실기는 유효한2차 후보가 정해진 뒤 한 묶음으로 준비한다. 최종 출하 결과는 source/build/hash·실제 검증·남은 사용자 행동을 구분해 보고한다.
