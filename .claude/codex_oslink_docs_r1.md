## R1. 조사한 루프의 한계를 제품 전체 부재/우열로 확대하지 않는다

신규 문서 17~29행의 제목 ‘OSLink에는 … 감시가 없다’, ‘OSLink 구조로는 … 잡히지 않는다’, ‘가져올 감시 설계는 없다’는 원자료 q1보다 강하다. q1은 **해당 감시 루프에서** 프레임 진행/API 경과 검사가 없음을 확인했으며 다른 함수·프로세스는 미확인이라고 명시한다. 같은 문서 25행의 미확인과도 충돌한다.

- 제목 예: ‘캡처 감시 — 존재·재시작 요청 확인, API hang 시간 감시는 미확인’.
- 시사점 예: ‘확인한 존재/플래그 루프만으로는 ReleaseFrame 정체 검출을 보장하지 못한다. GNLink의 5초 DXGI watchdog 계약을 유지하고 분리 후에도 별도 검증한다.’
- 약500ms는 q1의 **정적 추정 주기**로 표시한다. 실측 스케줄/복구 시간처럼 확인 항목 하나에 섞지 않는다.
- 100행 ‘APK를 분석하지 않아 없음’도 ‘미분석/미확인’으로 적어 기능 부재와 구분한다.

## R2. OS 로컬 입력 API와 네트워크 평문을 구분한다

신규 41행 ‘OSLink는 … 키를 평문 그대로 친다’는 q3에서 도출되지 않는다. q3은 로컬 Unicode INPUT/SendInput 경로와 포커스 보조를 확인했고 네트워크 입력 전체 경로·전송 보안은 미확인이다. q6도 채널 평문/암호화를 어느 쪽으로도 판정하지 않는다.

- ‘확인한 로컬 입력 경로는 Unicode INPUT 배열과 SendInput을 사용한다. 네트워크/IPC에서 credential을 별도로 보호하는지와 전송 암호화는 미확인’으로 바꾼다.
- GNLink sealed 비밀번호 경로도 최종적으로 로컬 SendInput을 쓰므로, SendInput 사용 여부를 sealed 보호와 대립시키지 않는다. 비교는 **GNLink가 명시적으로 설계한 목적 분리·일회 전달·재사용 방지 계약**과 OSLink 조사에서 확인한 로컬 입력/포커스 범위다.
- 45행의 GNLink 설명은 **이번 확정 설계의 목표**로 표시한다. 현재 제품이 이미 모든 잠금 평문 경로를 닫았다고 읽히면 안 된다(A6 미구현).

## R3. IPC와 인코더 위치의 확신도를 원자료에 맞춘다

신규 51~56행, 기존 문서 정정 블록/§5.1, history의 요약을 같은 수준으로 맞춘다.

- q2는 capture의 매핑 생성 코드, ldremote의 같은 이름 기반 매핑 소비 코드, VideoManager→ZEGO raw API 호출을 각각 확인했다. **매핑 뷰에서 모든 프레임 callback까지의 완전한 연결/모든 모드**는 미확인이다. 이를 생략하고 전체 제품 파이프라인이 배타적으로 확인됐다고 하지 않는다.
- 신규 56행 ‘캡처 프로세스에는 인코더가 없다’는 삭제하거나 ‘추적한 raw 제출 경로의 압축 생성은 ldremote의 SDK 경계 이후라는 추정 높음’으로 한정한다. ‘확인됐다(추정 높음)’도 확인/추정을 분리한다.
- 신규 53행은 **W×H×3/2·stride 구성 확인**, planar4:2:0과의 일치는 **추정**, 정확 SDK enum·IPC 형식·변환 위치는 미확인으로 적는다. IPC가 NV12/I420이라고 확정하지 않는 현재 방향을 유지한다.
- 과거 파이프 확정 설명의 철회는 OK다. 정정은 ‘이번에 확인한 공유 메모리/raw 소비 근거’로 쓰고 **어떠한 모드에서도 파이프 영상 전달이 없다**는 전면 부정으로 바꾸지 않는다.

## R4. 논리 스트림 유지와 SDK 인코더 인스턴스 유지를 분리한다

신규 63행 제목 및 75~83행은 q7의 핵심 한계를 누락한다. q7은 캡처 감시와 앱 publish/init 경로가 별개이며 특정 과거 로그에서 같은 스트림 문맥으로 처리가 재개됨을 확인했다. **SDK 내부 인코더 유지·재생성·재설정은 미확인**이다.

- 제목은 ‘캡처 재기동과 앱 퍼블리시 수명은 별개, SDK 인코더 수명은 미확인’ 정도로 한정한다.
- 75행 ‘재연결·인코더 재시작이 없다’는 ‘캡처 재시작과 논리 연결/코덱 재시작을 분리하는 **설계가 가능하다**. OSLink SDK 내부 인코더 동일성은 미확인’으로 바꾼다. 82행의 ‘실제 형태/인코더 유지’도 ‘raw IPC 관찰을 참고한 설계 대안’으로 맞춘다.
- 70행 ‘첫 복구 화면은 SDK 내부(GOP·손실 복구)에 맡겨진 것으로’는 ‘확인한 raw 경로의 압축 생성은 SDK 경계 이후로 추정되지만, **강제 keyframe/config 변경/손실 복구/GOP 중 첫 복구 조건과 시점은 미확인**’으로 적는다. q7은 GOP에만 맡긴다는 해석을 명시적으로 배제한다.
- 캡처+인코딩 워커가 죽는 경우에 GNLink 자체 barrier·ForceIDR·SPS/PPS key·incarnation·seed 게이트를 요구하는 설명은 **8월 §6 ADR 초안과 일치**한다. 이를 변경할 필요는 없다. 8월 문서의 권고와 **초안·승인 전** 상태도 유지한다. 새 문서 §4의 ‘§5.3’은 실제 참조 대상인 `OSLink_구조분석.md §5.3`로 명시한다.

## R5. LK/DW 기록의 증거와 현재 상태를 맞춘다

- 작업목록 LK 제목 ‘잠금 화면·로그인 전 화면에서 … 비밀번호 입력 수단0’은 과장이다. 지금 확인된 것은 **사용자 Host의 활성 콘솔 잠금 + 호스트IME 조합의 입력 실패/버튼 부재/기존 unlock 거부**다. prelogin에는 기존 버튼 경로가 있고 P1 평문 경로도 존재한다. ‘잠금 화면 로그인 경로 보완·로그인 전 화면 공통 UX/검증’처럼 수정한다. 새 호스트 A6 차단 뒤 APK0.2.30의 비밀번호 수단0은 **향후 호환성 영향**으로 구분한다.
- DW/history의 ‘자동 재연결 동작’은 **시간선·코드상 강한 정황, 분기 직접 로그 미확인**이라는 report의 한계를 보존한다. picker 원인과 27888 종료 사유도 실측한 전체 행동처럼 승격하지 않는다.
- LK/DW의 ‘Codex 판정 대기’와 history의 ‘다음: Codex 설계 판정’은 방금 회신한 `codex_lockkeys_dxgi_r1.md` 기준으로 **설계 판정 완료·구현 미완료**로 갱신한다. A6 호스트 차단 포함/APK0.2.30 영향, Bⓐ1 시험만 OK·출하 보류, Bⓑ2 보류를 반영한다. 별도 신규 제품 결정을 만들라는 요구가 아니다.
- ARSO는 보고에 있는 Security logon type 미확인 한계를 보존하고, 신규/이력에서 확정 실기보다 강하게 쓰지 않는다. OSLink 관련 history 요약도 R1~R4와 같은 증거 수준으로 맞춘다.
- CS 등재는 OK. **후속 검토 후보·ADR 초안 미승인·경계 판정/spike 전 production 착수 아님**을 명시한다. ‘LK·DW 뒤 착수’가 캡처 분리 제품 코드의 자동 착수 승인처럼 읽히지 않게 한다. 이번 위임은 작업목록 등재까지다.

## R6. 기록/커밋 범위

AGENTS Mandatory Workflow에 따라 `docs/구현계획.md`에 이 문서 작업의 **체크박스/진행 상태만** 최소 반영한다(예: OSLink 분석 문서화/전문 검토 상태). 새 조사 이력·서술은 history에만 둔다. LK/DW 제품 구현 완료를 체크하지 않는다. 따라서 보완 후보는 기존4파일 + 이 상태 파일이 될 수 있으며, 무관한 과거 계획 문구 전수 정정은 하지 않는다.

커밋 전 history에 전문 검토 반영 결과와 실제 다음 담당을 취합하고 해당 파일만 Git MCP Conventional Commit, push 없음. 최종 응답은 수정 후보 hash·검토 반영 위치와 commit을 구분한다. 수정된 문서 후보가 확정되면 내가 R1~R6 영향 범위만 재검토한다. 원자료 전체의 신규 분석은 요청하지 않는다.

## 통과한 부분과 검증 한계

- §4의 **캡처-only와 캡처+인코딩 fault domain 차이**, encoded-AU 복구의 barrier/key/seed 요구는 ADR 초안과 모순되지 않는다. 새 CPU raw IPC 대안을 확정 설계로 채택한 것도 아니다. 위 R4의 보장 표현만 줄이면 된다.
- 신규 문서/기존 문서 diff에 OSLink 의사코드·함수 본문을 이식한 부분은 보이지 않는다. API명·객체명·짧은 문자열·주소/바이트 근거와 자체 설계 서술이다. 제품 코드 변경도 없다. ‘원자료의 출처 제한을 넘는 코드 복제가 없다’는 판단은 **후보 문서 범위**에 한정한다.
- README·q1~q7 전체와 후보4파일·8월 §5/§6 ADR을 직접 읽었다. raw PE/REA 디컴파일을 독립 재실행하거나 공식 Ghidra digest를 새로 조회하지 않았다. ‘검증용 독립 대조’라는 귀속은 그 보고를 인용한 것으로 유지한다.
- 기본 `git diff --check`는 기존 CRLF 파일의 추가행에서 CR을 whitespace로 보고 exit1이었다. **CR-at-EOL을 허용한 동일 diff 검사 exit0**, 실제 trailing blank 문제는 확인되지 않았다. 이 때문에 역사 문서 전체 line ending을 바꾸는 보수는 요구하지 않는다. 제품 빌드·실행 시험은 문서 변경에 필요하지 않다.

Codex는 공개 문서를 직접 편집/커밋하지 않았고 이 미추적 `.claude/` 판정서만 작성했다. 최종 문서 승인은 보완 후보 재검토 뒤다.
