# rel-0160 — APK0.2.30 prelogin 실패 표시 판정

`t-r639inm8 / rel-0160 / kind=decision / reply_to=remote#pvbntb3z` · 2026-10-20

**PC 단독 prelogin v1의 알려진 호환 한계로 명시하고 릴리스 준비를 진행한다. “Connecting…” 잔류만으로 이번 PC 게시를 차단하거나 APK 동반 게시를 요구하지 않는다.** 새 호스트 refusal 메시지도 이번 필수 보수로 요구하지 않는다. 사용자 APK0.2.30 유지/재게시 금지 지시는 그대로다. 이 결정은 고정 출하 후보 검수·사용자 게시 지시·서명/배포·외부 검증을 대체하지 않는다.

## 판정 근거

게시 APK의 SHA256 `e6a6eecbf129f92998d5c4d4e2844057485315489c001023b24f5966a93608cf`를 실제 dist 파일에서 다시 확인했다. APK를 고친 시험이 아니며 CA 미주입 때 실제 TLS 거절/디렉터리 요청0이 나온 대조도 보고에 있다. AVD OS hosts/시험 CA 주입은 격리 시험 차분으로만 인정한다.

직접 읽은 보고·시나리오 로그와 화면 `s2_90s.png`는 다음을 구분한다.

- 지원하는 일반 Host 경로는 선택→첫 프레임·park 재사용·재선택·연결 해제의 5개 검사를 통과했다. 동일 세션의 이전 PC 버전 A/B라는 뜻은 아니다.
- 미지원 prelogin 경로는 첫 비허용 요청 type28이 약4ms 후 거부됐고, 앱은 약12초 후 HOSTS/error로 돌아왔다. 90초 동안 접속 요청은 1회이며 재시도는 관측되지 않았다. worker는 살아 있고 후속 PC viewer 새 세션 3회도 유지됐다는 근거가 있다.
- **앱 화면에는 실패 문구가 없고 Connecting to SHOTAN…가 남는다. 이 사용자 표시 결함 후보를 인정한다.** 내부 status=error만으로 화면 실패 표시가 됐다고 판정하지 않는다. 일반 Host 연결 유실 대조가 없으므로 구형 APK의 기존 공통 결함이라고도 단정하지 않는다.

r22의 “실패를 알리거나 종료함” 조건 중 종료/목록 복귀는 충족하고, 명시적인 화면 실패 표시는 미충족이다. 이번에 지원하는 행동은 **새 PC viewer의 로그인 전 접속**이며 구형 휴대폰 prelogin은 명시적으로 미지원이다. 지원 일반 접속과 PC viewer 복구가 유지되고 재시도 루프/호스트 중단이 관측되지 않은 상태에서, 이 미지원 조합의 잔류 문구는 PC v1 핵심 행동의 실패로 보지 않는다. 사용자 행동 완료 기준을 구형 APK까지 모두 통과했다고 바꾸는 결정이 아니다.

## sentinel과 무부작용 증거의 한계

조기 sentinel 큐잉은 **미실행**이다. 실제 adb 입력은 +4.4초 이후였고 입력 가능한 컨트롤도 없었다. 이를 “sentinel 송신 차단 PASS”로 쓰지 않는다. 이번 정상 시작 경로에서 첫 거부 요청은 창 목록, InputEvent/자격 처리/재부팅 시도는 관측0이며 구형 UI로 영상도 전달되지 않았다는 결과만 인정한다. 구형 client의 모든 API·일정에서 문자 송신이 불가능하다는 보장은 아니다.

앞서 읽은 구형 scheduler의 list 우선순위 및 실제 게시 APK의 미지원 경로 종료를 함께 고려해 **현재 UI로 도달한 정상 시작 경로**의 제한된 거부 근거로 수용한다. 입력란 없는 화면에 대한 추가 adb 시도나 이를 위해 APK를 수정한 시험을 이번 새 게시 gate로 요구하지 않는다. 나중에 구형 UI에서 자격 입력까지 도달하거나 문자 payload/재부팅/자동 재접속 루프가 관측되면 영향이 달라지므로 그때는 호스트의 사전 admission 경계를 재검토한다.

기존 host allowlist·문자 payload 필터·인증·봉인 경로를 유지한다. 구형 UI에 오류를 띄우기 위해 비허용 창 목록을 허용하거나 일반 입력/자격 동작으로 우회하지 않는다. 구형 APK가 이해하는 앱 오류 경로와 상태 갱신이 확인되지 않은 새 refusal 메시지는 표시 개선을 보장하지 못하고, 이번 PC 릴리스에 별도 protocol 변경을 추가할 근거도 없다.

## 기록 및 사용자 안내

릴리스/실기 안내에는 아래 내용을 함께 적는다.

> 로그인 전 원격 접속과 Windows 로그인은 이번 새 PC viewer에서 지원합니다. 휴대폰 APK0.2.30의 로그인 전 PC 접속은 지원하지 않습니다. 시도하면 목록으로 돌아오며 “연결 중” 문구가 남을 수 있습니다. 이 상태에서 더 기다려도 연결되지 않습니다. 새 PC viewer를 사용하거나 대상 PC에서 먼저 Windows에 로그인한 뒤 휴대폰으로 일반 접속하세요.

현재 “PC가 ONLINE으로 보임”은 휴대폰 prelogin 지원 표시가 아니다. 표시 결함 후보는 기능 기록의 알려진 한계로 남기고, 추후 APK 변경이 허용될 때 실패 상태 갱신 범위를 검토한다. 지금 일반 Host 강제 유실 대조나 별도 문구 수정 task를 연쇄 생성해 PC 릴리스 준비를 멈추지 않는다.

보고를 취합할 때는 관측/미실행을 정확히 유지한다.

- host 시험물은 406f563 기준의 제품 동등 빌드이며 로그 버전은0.2.159다. 실제 0.2.160 출하 host를 실행한 결과라고 쓰지 않는다. 직접 비교한 `406f563→c5adb6c`에는 product_version.hpp와 작업목록 변경이 있으므로 “제품 diff0”은 **버전 제외 동작 코드 동일**로 정정한다.
- steps.txt의 초기 CA 단계에는 두 카드 목록 assertion FAIL이 별도로 있다. 이후 일반 Host 5/0·prelogin 관측 및 후속 연결과 구분해 원본을 보존한다. 초기 준비까지 전부 PASS였다고 합산하지 않는다. 이 한 건의 원인을 이번 근거 없이 단정하지 않는다.
- forwarder 없이 끊긴2회 및 일반 Host 대조의 동일 실패, forwarder 사용 후3회 유지도 함께 남긴다. ICMP 가설은 미확정이다. 실제 SYSTEM/Winlogon·SCM·UAC·재부팅 실기는 계속 별도다.
