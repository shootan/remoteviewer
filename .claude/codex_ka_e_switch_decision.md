근거는 이미 확정한 `codex_keepalive_r2_kept_model.md`의 명시 연결→목록 첫 전환/지원 없는 대상 계약이다. 검증용의ⓐ 의견에 동의한다. 단 `plan_ka_e_wiring_r1.md` 말미의 작업용 제안은 현재 **ⓑ**로 쓰여 있어 인계 본문의 작업용ⓐ 표기와 다르다. 이 결정으로 정본을ⓐ 하나로 갱신하고 과거 제안/대기를 추측하게 하지 않는다. 별도 사용자 승인 왕복은 필요 없다.

## 스위치 의미를 정확히 고정

`Preconnect.SEND_TO_REAL_HOSTS=false`는 이번 e에서 **최근 이력을 이유로 새 자동 standby 준비를 시작하는 경로**(앱 시작/복귀·목록 poll/online 이벤트·자동 planner 재시도)를 막는 것으로 정의한다. 사용자 탭과 그 사용자가 목록으로 나가며 남긴 연결의 대기 유지까지 막는 전역 transport 차단 스위치로 설명하지 않는다. 기존 “false면 아무것도 보내지 않는다” 주석·로그·시험은 새 범위로 맞추고, 필요하면 자동 최근 준비임이 드러나는 이름으로 정리한다.

특히 **기존 lease의 UDP Ping은 끄지 않는다.** OFF에서 명시 행동으로 만든 lease도 Ping을 보내야20초 liveness가 유지된다. “heartbeat를 막는다”가 목록 갱신 이벤트에 의한 새 자동 admission을 뜻한다면 막지만, 확인된 lease의 생존 Ping을 뜻한다면 허용한다. 관찰/접수 실패 뒤 무제한 재시작을 허용한다는 뜻은 아니며, 같은 owner/key의 lease 회복은 기존 bounded backoff·권한 확인·억제 정책 안에서 수행한다. OFF가 새로운 최근 Host를 몰래 준비하는 경로로 사용돼선 안 된다.

| 상황 | OFF의 동작 |
|---|---|
| 앱 시작/복귀·목록 갱신만 발생 | 최근3대 자동 admission 시작0. 화면/입력 자동 활성화0. |
| 사용자가 지원 PC를 사용한 뒤 목록 복귀 | 활성 session 종료/fence→기존 lease로 복귀 또는 첫 standby 전환. 확인된 lease의 Ping 유지, 준비된 PC 재tap은 사용자 activation. |
| 구 Host/prelogin/raw-IP/지원 확인 실패 | 지원을 꾸미지 않는다. 명시 일반 연결은 제공하되 목록 복귀는 안내+세션 종료. 자동 legacy Hello fallback0. 미확인/일시 실패를 구버전 확정으로 단정하지 않는다. |

이 결정은 **스위치의 제품 의미**를 정한 것이며 미검수 코드의 실 Host 실행/게시 승인이 아니다. 현재 KA N2-a/b 반려(`codex_keepalive_r2_src_r3.md`)는 그대로다. 동일 task에서 보수/배선·격리 시험을 계속하고, SOURCE·독립 행동 검증을 통과한 통합 후보로 출하한다. OFF라는 이유로 새 명시 전환 경로의 취소·수명 검사를 생략할 수 없다.

## 구 Host의 사용자 행동 변화/릴리스

기존0.2.30 이후의 **5분 park 유지가 구 Host에서는 사라지고**, 목록 복귀 후 재tap이 cold connect가 되는 변화는 명시적으로 수용한다. 이것은 모델 A의 호환 정책이며 미지원 Host에 옛 parked control을 남겨3대 상시 유지처럼 보이게 하지 않는다. 활성 연결 중 임의로 끊는 변경은 아니고 사용자의 목록 복귀에 적용한다.

R2의 Host 지원을 포함한 PC0.2.164와 APK0.2.33을 함께 검증·게시한다는 계획은 이 방향과 맞다. 다만 **자동 업데이트 대상=이미 지원 버전 실행 중**은 아니다. 각 Host의 실제 지원/admission을 기준으로 판단하고, PC 미업데이트/오프라인/지원 확인 실패에서도 종료·재접속·미지원 안내가 동작해야 한다. “0.2.164로 업데이트하면 유지” 안내는 그 버전의 지원/게시가 실제 확인된 뒤 사용한다. 요청 없는 사용자 PC 설치/재시작은 하지 않는다.

검증용은 게시 안내에 예를 들어 “구버전 PC에서는 PC 목록으로 나가면 연결이 닫힙니다. 대기 연결을 지원하는 PC 버전으로 업데이트하면 유지됩니다”를 넣고, 실제 반영 버전을 함께 명시한다. 소스의 feature 존재나 계획 번호만으로 지원을 확정하지 않는다. ON을 목표로 한 최종 독립 검증을 통과하면 승인된 정상 릴리스 절차를 이어가며, 이번 결정 때문에 별도 go 대기를 만들지 않는다.

## 배선/검증에서 유지할 경계

- M1은 `resumeKept/park_reuse`의 실제 제거 및 **새 활성 session**의 요청 상태 초기화로 닫는다. 계획 선언만으로 닫지 않는다. A의 미응답 UA-2 요청→목록→B→A 새 활성화에서 옛 응답/asked 전파0·자동 backend 재전송0·새 Host 상태 표시를 확인한다.
- 목록 복귀 후 Disconnect 반환→정확한 op의 SessionOver→lease 재개 순서를 지킨다. `Parked && !handedOff`라는 로컬 상태만으로 Host grant가 끝났다고 주장하지 않는다. ReturningToStandby의 확인/유한 회수는 기존 모델 A 계약을 그대로 따른다.
- OFF+지원 fixture에서 명시 전환/Ping 유지/재tap, OFF+구 Host에서 안내/종료/명시 cold 재접속, ON에서 최근3대 자동 준비를 각각 실제 APK UI·처리 결과로 확인한다. OFF의 자동 admission0, onStop·계정 전환·명시 해제 후 old owner의 재생성0, 다른 기기 active 무간섭·자동 재탈취0도 묶는다.

검증용은 이 결정을 기존 e 정본에 취합해 같은 작업용1에게 전달한다. 제품 코드/스위치 변경·빌드·실행·설치·삭제·commit/push는 Codex가 하지 않았다. 이 미추적 판정서 외 history/계획·Git MCP commit은 해당 구현/통합 작업에 취합한다. 사용자 현재 조치 없음.
