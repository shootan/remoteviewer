## Codex 검토

2026-09-28 **r2 기준(이 검토가 r1을 대체)** — main 머지 후 main 직접 빌드·게시, 검증용 번호 예약, 뒤 작업용의 main 통합·자체 재검증 방향에 동의한다. 실제 push/게시를 이번 검토에서 실행한 것은 아니다. r2 diff에 아직 남은 아래 문구를 한 번에 정합화하면 되며 제품 작업의 선행 대기로 만들지 않는다. release 브랜치 생성/FF 절차에 대한 이전 요구는 폐기한다.

1. **Codex 검수가 필수/선택으로 충돌.** AGENTS 개발 프로세스2·역할 분담은 `검증용 독립 검사 + Codex 검토`인데 CLAUDE 신설 검수 절은 `필요하면 Codex 검토`다. 사용자 원문대로 제품 작업의 최종 검수는 둘 다로 통일하되 기능 단위로 한 번, 중간 커밋마다 재승인하지 않는다고 명시한다.

2. **사용자 창구 변경의 잔존 모순.** AGENTS의 문서·정책 전용 흐름과 CLAUDE 역할별 책임의 문서 전용 흐름은 아직 `Codex 최종 보고`다. `Codex 독립 검토 → 검증용 기록/커밋 → 사용자 창구 세션 최종 보고`로 바꾼다. 검증용이 버전 파일을 바꿀 수 있다는 예외도 AGENTS 제품코드 수정 금지 절·CLAUDE 하단 원칙에서 신설 절을 참조하게 한다.

3. **두 절이 서로 최우선이라고 함.** 두 파일 모두 09-28 신설 절은 '아래와 충돌하면 우선', 09-11 절은 '다른 운영 절차보다 우선'이다. '역할·머지/push·릴리스 담당·보고 창구는09-28, 그 외 연속수행·중복요청 방지 원칙은09-11 유지'처럼 우선 적용 범위를 한 방향으로 정리한다. 삭제/비밀/사용자 중지 등 상위 경계는 그대로다.

4. **재검사 비용을 무조건 강제하는 문장 완화.** 고정 commit의 독립 검증은 필요하지만 모든 작업에 fresh 빌드+격리 e2e+사용자 파일 전수 해시를 요구하면 기존 '고정 산출물 독립 실행 우선/영향검사만'과 충돌하고 다시 정체를 만든다. 필요한 경우 독립 빌드, 변경에 맞는 실제 행동 검증, 실사용 파일을 건드릴 위험이 있는 승인 시험에만 지정 파일 전후 보존 확인으로 한정한다. 테스트 개수나 작업용 주장만으로 승인하지 않는 원칙은 유지.

5. **신규 병행 배정과 동일 작업 이관을 구분.** 새 독립 작업을 다른 worktree에 배정하는 것은 바로 가능하다. 같은 작업을 이관할 때는 원 담당의 변경/실행 중단과 소유권 이동이 확인된 뒤 후임이 시작해야 한다. 단순히 바쁜 상대에게 통지 한 번만 하고 두 작업용이 동일 task를 수행하게 하지 않는다. main을 기본 base로 하되 선행 검수 commit이 필요한 의존 작업의 정확한 base 사용은 허용한다.

6. **r2 main 직접 릴리스의 정확한 순서/동시 변경 방지.** `검수한 commit까지 main 머지 → main 통합 빌드·영향 회귀 → 정상 push → main 버전 commit → 그 commit 고정 빌드·서명·게시·외부 확인·dist 보존 → 버전 commit 최종 push/원격 정합 확인`으로 순서를 명시한다. 여러 완료 작업은 한 검수 묶음·통합검증·릴리스로 처리 가능하다. 머지 직후 push부터 하고 뒤늦게 통합 회귀를 하는 것으로 읽히지 않게 한다.
   main worktree에서 빌드하므로 검증용은 버전 commit부터 산출물 검증까지 그 HEAD와 추적 파일을 다른 merge/edit가 바꾸지 못하게 릴리스 구간을 직렬화한다(작업용 전용 worktree 개발은 계속). 빌드 중 변경이 확인되면 해당 산출물 게시를 중단하며, 검수 source/버전·build commit/공개 artifact hash를 연결한다. 빌드·게시 실패는 실패 단계/정확한 상태로 보고하고, 이미 push/게시한 버전·URL을 재사용하거나 강제 reset/rebase하지 않는다.
   병렬 항목의 '먼저 끝난 것'은 **먼저 검수까지 통과한 고정 commit**을 뜻해야 한다. 뒤 작업용이 main을 합쳐 충돌을 해결했다면 원래 commit 검수로 대체하지 말고 새 통합 commit의 변경분·관련 회귀를 검증용+Codex가 확인한다. 검증용의 '머지 예외'는 검수된 결과를 통합하는 Git 작업이지 제품 충돌을 독단적으로 고치는 권한이 아니다. 정상 버전-only 절차에 별도 단계별 go는 요구하지 않는다.

7. **문서-only 예외와 제품 final 확인을 일관되게 유지.** 검증용이 직접 쓴 정책을 자기 승인하는 것은 금지, Codex가 독립 검토한다. 반면 검증용이 main merge/버전/서명/게시를 수행하는 것은 사용자 승인된 release 역할이므로 예전 '제품코드 수정 금지'를 이유로 중간에 멈추지 않는다. push 허용은 검수된 commit의 정상 main push로 한정한 현재 문구를 유지하고, force/이력 재작성·운영 설치·광역 NAS 권한 변경까지 승인한 것으로 확대하지 않는다.
