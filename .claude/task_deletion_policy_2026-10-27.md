## 이미 적용할 운영 방침

- 정리 목적의 삭제 후보는 **D:/remote/remote/.claude/deletion_candidates.md** 한 곳에 누적한다. 작업 중에는 삭제 권한을 사용자에게 묻지 않는다. 사용자 정리 요청 때 검증용이 목록을 한 번에 제시하고 명시 승인분만 삭제한다.
- 후보 등재나 상태가 후보/언제든이라는 것은 삭제 허가가 아니다. 미승인 삭제를 제품 검토 blocker/중간 권한 질문으로 올리지 말고 보존·목록 기록으로 처리하며 독립 작업을 계속한다.
- 기존 root 밖 삭제 금지는 유지한다. 유일한 현재 명시 예외는 **해당 시험이 CreateNew로 직접 만든 C:/work/gnlink-wt/SLOT_REQUEST.txt 1인스턴스의 종료 삭제**다. 남이 만든/stale slot·TEMP·scratchX·worktree 등에는 확대하지 않는다.
- 현재 목록에 scratchX 등 기존 후보가 이미 있어 중복 추가하지 않는다. 실제 삭제 때는 승인된 정확한 대상·보존 조건·작업 상태·링크/실경로를 다시 확인한다. 정리 전 일괄 승인도 현재 작업 자료를 자동 폐기하는 허가는 아니다.

## 영속 정책 문서의 최소 변경

main worktree의 다른 미결 정책/제품/릴리스 변경을 섞지 않는다.

1. AGENTS.md 가장 상위 정책의 **필요시 권한을 물어본다**를 이번 지시에 맞게 좁혀 갱신한다. root 밖 삭제 금지, 작업 중 삭제 권한을 묻지 않고 후보로 보존, 사용자 요청 시 일괄 승인 후 실행, 위 slot 한 파일 예외만 상위 원칙으로 적는다. 기존 다른 역할/배포 규칙은 재작성하지 않는다.
2. CLAUDE.md에는 구체 절차를 정본으로 둔다: 중앙 후보 경로, 중복 방지/소유·조건 기록, 검증용 한 창구의 사용자 요청 시 목록 제시/승인 범위 실행, 다른 삭제 질문 금지, 진행 중 보존과 slot 예외. AGENTS와 장문을 중복하지 않는다.
3. 저장소 규칙대로 docs/history.md에 목표/변경파일/문서 diff 검토/다음 담당을 기록하고, docs/구현계획.md는 기존 에이전트 운영 정책 checkbox/상태만 갱신한다. 별도 주간 history 파일이나 계획의 서술 이력은 만들지 않는다.
4. .claude/deletion_candidates.md에는 이 절차와 slot 예외를 분명히 하되 기존 후보/증거/보존 조건을 지우거나 삭제하지 않는다.

고정 diff를 Codex에 전문 검토로 보내고, 통과 후 위 관련 파일만 Git MCP로 Conventional Commit한다. 제품 변경/빌드·삭제/정리 실행은 없다. **이 문서 task만으로 독립적인 push를 추가하지 않는다.** 기존 승인된 릴리스의 관련 문서 push와 연결할 때만 그 범위를 따르며 새 push 권한을 묻지 않는다.
